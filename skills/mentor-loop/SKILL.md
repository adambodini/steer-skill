# Mentor loop

The mentor is the challenger for the channel standards. One channel per session. Over time every standard becomes mentor-tested, and each change carries its evidence.

## Before the session: the one-pager
Built from the channel's standard (e.g. `meta-playbook`, `google-ads-channel-standard`). One page, no more.

1. **The principles** for the chosen channel, one line per pillar.
2. **Where I might be wrong:** three to five points, ranked by how much they'd change the standard if wrong. Take them from:
   - TEST items already in the standard that have no result yet;
   - places where sources disagree with each other;
   - principles that rest on one source, a vendor source or no source.
3. **For each point:** what the standard says now, the case against it, and the question for the mentor.
4. **What I'm not asking about:** areas already settled, to save time.

Rules for the brief:
- Generic only. No client names, client numbers or employer data. If an example is needed, describe its shape, not the brand.
- Don't overstate. If a point rests on weak evidence, say so.
- Adam reviews and approves the brief before it goes to the mentor. **This skill never sends it.**

## After the session: logging
Work from Adam's notes or the transcript. For each challenge:

| Field | What to write |
|---|---|
| Principle | Which line in the standard it challenges |
| Challenge | What the mentor said, in a sentence |
| Type | `TEST` (needs evidence), `OPEN` (needs checking) or `CHANGE` (Adam accepts it now) |
| Test | How it would be tested: what, where, how long, what result would change the standard |
| Status | Not started / running / result in |

Then:
1. Add `TEST` and `OPEN` items to the standard's tests section.
2. Add a change log line: date, "mentor session", and what was added.
3. A `CHANGE` edits a principle only when Adam has said so, and the change log records that it came from the mentor.
4. When a test result comes in, log the result and the change it led to (or "no change").

## Rules
- Record what the mentor said, not an interpretation of it. If the notes are unclear, mark it `OPEN` and ask Adam.
- A mentor view is a challenge, not a decision. Nothing in the standard changes without Adam.
- Test results are logged as generic evidence: what happened, not whose account it happened in.
